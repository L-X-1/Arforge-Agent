## Decision rules

A source capability is counted as preserved only when one of the following is
true:

1. the target already has an equal or stronger observable contract and fresh
   regression evidence;
2. the capability has been implemented as a native target vertical slice; or
3. it is deliberately rejected because it would duplicate a weaker runtime,
   with the stronger replacement named.

A similarly named module is not evidence. Roadmap prose, generated help text,
and an uncalled implementation are not evidence. External signing, hosted
services, credentials, and production infrastructure remain blocked until
their owner supplies real coordinates and authorization.

## Final implementation disposition

1. All source contracts are either natively integrated or retained through a
   named equal-or-stronger target implementation.
2. Full regression, generated-client verification, migrations, type checks,
   production builds, and strict brand audit have fresh passing evidence.
3. Production publication, signing, and hosted-service coordinates remain
   intentionally outside this local fusion and require separate owner
   authorization.

## Evidence semantics

- **equivalent retained** means the mature target behavior remains the owner and
  has a concrete code/test surface.
- **integrated** means a new native vertical slice exists and affected checks
  pass.
- **partial** means useful behavior exists but one or more source invariants
  have not been proven.
- **open** means the source contract is real and no equal target contract has
  yet been demonstrated.
- **blocked** is reserved for a named external dependency, never for unfinished
  local engineering.
