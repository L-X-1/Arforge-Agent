# Session LLM Runtime Boundaries

`../llm.ts` is the arforge session LLM service. It owns arforge concerns: auth, config, model/provider resolution, plugins, permissions, telemetry headers, and runtime selection. It is the only file in this area that should know about the full session request shape.

This folder contains adapters behind that service boundary:

- `ai-sdk.ts` converts AI SDK `fullStream` parts into `@arforge-ai/llm` `LLMEvent`s. This is the default runtime path.
- `native-request.ts` converts arforge's normalized session input into a native `@arforge-ai/llm` `LLMRequest`. It does not execute requests.
- `native-runtime.ts` is the opt-in native runtime adapter. It decides whether a selected model is supported, builds the native request, bridges arforge tools into native executable tools, and delegates transport to `LLMClient` / `RequestExecutor`.

## File Structure

```txt
src/session/
  llm.ts                    session-owned orchestration and runtime selection
  llm/
    AGENTS.md               boundary notes for the adapter layer
    ai-sdk.ts               AI SDK fullStream -> @arforge-ai/llm LLMEvent adapter
    mature-binding.ts       metadata-only run/attempt/request binding projection
    native-request.ts       arforge/AI SDK-shaped input -> @arforge-ai/llm LLMRequest
    native-runtime.ts       native runtime gate, tool bridge, and LLMClient handoff
```

Integration points:

- `../llm.ts` imports `LLMClient` from `@arforge-ai/llm/route`; native execution is the only path that calls it directly.
- `../llm.ts` imports `LLMAISDK` from `./llm/ai-sdk`; the AI SDK path still calls `streamText(...)` locally, then adapts `result.fullStream` into shared `LLMEvent`s.
- `../llm.ts` imports `LLMNativeRuntime` from `./llm/native-runtime`; this is the runtime-selection seam. Unsupported native requests return a reason and fall back to AI SDK.
- `mature-binding.ts` is the only mature-side binding projection. It hashes
  the exact native RequestEnvelope transiently (or normalized AI-SDK input on
  fallback) and returns bounded digests only; `llm.ts` may publish the
  `SessionEvent.RequestBindingPrepared` durable metadata projection, but it
  must never return or persist message bodies, tool arguments, headers, auth,
  or executor functions.
- `native-runtime.ts` imports `LLMNative` from `./native-request`; this keeps request lowering separate from transport and tool execution.
- `native-request.ts` is the only adapter file that should construct `LLM.request(...)`, `LLM.model(...)`, `Message.*`, `SystemPart`, `ToolCallPart`, `ToolResultPart`, or `ToolDefinition` values from `@arforge-ai/llm`.
- `ai-sdk.ts` and `native-runtime.ts` both emit `@arforge-ai/llm` `LLMEvent`s so downstream session processing does not care which runtime handled the request.

Keep new integration code on one of these seams. Avoid importing session services into `native-request.ts`; pass normalized data through `RequestInput` instead.

## Runtime selection

Both runtimes converge on the same `LLMEvent` stream consumed by the session processor. The gate is per-request: a single session can route some calls through native and fall back for others.

```txt

│                                      │

│                                      │

│                                ╭───────────╮
│                              ╭─╯           ╰─╮
│                              │  native gate  │
```

`native-runtime.ts` evaluates the gate and either bridges into `@arforge-ai/llm` or returns control so `llm.ts` can take the AI SDK path. Tool execution stays arforge-owned in both branches; only request lowering and transport differ.

Safety boundary:

- AI SDK remains the default.
- `ARFORGE_EXPERIMENTAL_NATIVE_LLM=true` or the umbrella `ARFORGE_EXPERIMENTAL=true` opts in. Native is not a global replacement.
- Native execution currently supports OpenAI, arforge-managed OpenAI-compatible, and Anthropic API-key paths backed by `@ai-sdk/openai`, `@ai-sdk/openai-compatible`, or `@ai-sdk/anthropic` catalog entries.
- Unsupported providers, OpenAI OAuth, and missing API-key cases fall back to AI SDK.
