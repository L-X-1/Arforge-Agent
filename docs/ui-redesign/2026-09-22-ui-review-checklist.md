# 设计审查与实施门禁
日期：2026-09-22

## 本轮提交
- 完整桌面/Web 设计计划，56 个画面，7 个分组。
- 浅色、深色、手机、窄窗口，以及常规/异常/弹窗状态。
- 源码能力与页面保留矩阵，29 条映射的设计归属。
- 独立 HTML 与 PNG 图片；示例数据，不调用 Server。
- 目前仍是计划环节，不修改应用源码、运行界面、配置、数据库，不重启应用。

## 建议审查顺序
1. 01 主会话、02 深色、03 首页：整体气质、阅读宽度、侧栏和输入区。
2. 05-17 工作台与预览：文件、差异、浏览器、PDF/Office/HTML、终端和执行。
3. 18-28 会话管理：目标、队列、定时、触发、等待、团队、回退、反馈与后台任务。
4. 控制中心与设置：记忆、演化、运行时、扩展、权限、治理、诊断、运维、服务商与模型。
5. 状态、弹窗、审批、内容排版和多尺寸画面。

以预览索引中的实际标题和编号为准，不把本段分组范围当作新增路由。

## 审查清单
- [ ] 用户消息浅灰轻气泡，助手回复无外框。
- [ ] 左侧历史刻度存在，卡片覆盖而不挤动正文。
- [ ] 触屏历史先预览再跳转，可关闭、可点外部关闭，无倒计时。
- [ ] 双层一体输入区和已有工具入口清晰。
- [ ] 有序列表是用户选择的 Noto Serif SC；普通正文与无序列表不跟着改成宋体。
- [ ] 17px 正文与明确的段落/标题/引用层级符合预期。
- [ ] 管理功能仍可发现，简洁不是删除功能。
- [ ] 状态、危险操作和作用域说明明确。
- [ ] 手机、窄窗口和深色方向可接受。
- [ ] 明确区分设计示例、真实运行状态和未完成专项。

## 审查反馈格式
使用“画面编号 + 区域 + 希望修改之处”，例如“01 输入区：工具栏再紧凑一些”。
如果整体方向通过但少数部分需改，可只批准未受影响的设计；修改不自动授权代码实施。

## 进入实施的唯一门禁
用户明确说“执行重构”或等义指令。此前不改应用界面。
批准之后仍需按现有包级规范，小范围修改、最小测试/typecheck、必要浏览器与桌面回归；不跳过类型检查，不清空用户设置，不移除现有功能。

## 本轮预览验收与应用验收的区别
本轮只核对设计文档、覆盖映射、预览页面是否能渲染、图片是否生成，以及关键浅深色/窄屏画面的可读性。
独立原型只模拟部分交互；键盘完整可达性、真实历史加载、API 权限、原生桥接、文件保存与运行时性能必须在应用实施后验证。
不把“渲染出图片”记成“56 个业务功能测试通过”。
