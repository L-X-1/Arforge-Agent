# Arforge 产品体验与本地可用性审查

- 日期：2026-08-15
- 对象：Arforge 桌面端本身；外部项目仅作为测试载荷
- 计划基线：Arforge-最终详细实施计划-V2-2026-08-11.md
- 范围：开发完善与本地交付；不包含发布、部署、签名、canary 或 rollback

## 结论

Arforge 的本地后端能力已经达到“受控本地使用”水平，核心会话、权限、目标、任务、记忆、工作流和后台任务均有持久化实现与回归证据。产品当前可进入本地 Beta 使用，但还不应宣称为无需学习成本、面向所有用户的成熟 1.0：主要差距已经从“功能缺失”转为“入口过多、内部术语过重、运行状态不够直观、进阶能力缺少引导”。

本轮首先修复了三个直接影响用户判断的问题：

1. 会话页接入已有但此前未使用的常驻执行状态条，明确显示“准备就绪 / 正在执行 / 等待授权 / 等待回答 / 正在重试 / 执行完成 / 存在失败步骤”。
2. 失效权限请求不再显示误导性的通用失败；若请求已被其他窗口、自动规则或运行流程处理，界面会清除旧请求并说明已自动刷新。
3. 设置与控制中心采用渐进披露：常用入口默认显示，高级自动化、扩展、诊断与治理入口折叠；中文以用户意图为主，同时用括注保留 Provider、Memory、Workflow、Plugin、Skill、Server API 等专业术语。
4. 增加首次使用三步引导和新手/日常开发/专业审查三个任务示例。示例只填入输入框，不自动发送，也不修改项目文件；用户可跳过并能从“设置 > 通用”重新打开。
5. 修复 Personal Workspace 的挂载时序：后端快照原本正常，但前端在 Location 就绪前提前返回且不再重试，导致页面空白。现在会在目录就绪后自动加载，并提供错误/空状态、中文状态标签和安全边界说明。
6. Personal Workspace 的 50 个会话、30 个后台任务不再一次性铺开；默认各显示最近 8 项，可由用户明确展开全部。
7. Agent 扩展页不再显示 `agent-capability-retired` 原始 JSON；对于当前运行时不提供的旧命令/Hook 检查，改为说明其不影响 Skill 与 Workflow。
8. 会话路由改为按需加载，主入口包由约 3449 kB（gzip 1008 kB）降至约 2646 kB（gzip 755 kB）。
9. 后台自动任务创建采用渐进披露：默认只要求任务名称、任务内容、运行时间和确认方式；Cron、请求标识、凭据边界、免打扰与预算限制移入“高级设置”。
10. 常见时间提供“每天 / 工作日 / 每周一 09:00”预设；未知 Cron 仍可通过高级设置编辑，不削弱专业能力。必填项与客户端错误现在靠近创建按钮并通过 `role=alert` 公告。
11. 任务卡片不再在主信息层显示 revision、毫秒和 micros，改为友好时间及成本预算占比。列表默认最多显示 6 项，用户可明确展开全部。
12. 会话控制中心在宽屏标题栏显示文字标签；全局设置中的禁用会话功能改为给出可执行路径：“先打开会话，再点击会话顶部的会话控制中心”。
13. 团队页改为“协作团队与消息”，创建表单使用“团队名称 / 协作目标”等用户概念，不再使用发布场景占位文案或把 Team、revision 作为主界面信息。
14. 团队页明确呈现多代理边界：只有任务能拆成清晰角色时才建议使用；小任务单代理更简单且通常更省成本；当前证据不支持仅为提速开启团队。这与阶段 8.2 的 `DO_NOT_PROMOTE` 结论保持一致。
15. “控制操作审批”从右下角悬浮层移入新版左侧边栏，位于“已归档”和“设置”之间，与其他工具项共享菜单行、焦点、悬停和数量徽标样式，不再遮挡会话内容或输入区域；旧版布局保留兼容入口。
16. Workflow 主视图不再直接铺出 `waiting_approval`、`acceptEdits`、节点 kind、`run_id` 和原始时间戳：状态、节点类型、权限、进度、尝试次数、依赖和时间均转为用户语言；ID、定义路径、访问范围等保留在可展开技术详情。预览明确说明“不调用模型或执行步骤”，运行详情增加语义化进度条、失败原因和空状态。
17. 修复 Workflow 列表到预览/启动的 Windows 路径合同：列表现在返回工作区相对路径，服务端统一解析并拒绝越出工作区的路径。此前绝对路径会被重复拼接，导致用户看得到定义但无法预览。
18. 桌面 E2E 可直接运行最新开发构建，无需打安装包；每轮创建独立 home、工作区、数据库和 Electron profile。开发模式尊重显式调试端口，不再无条件占用 9222；重复运行器默认连续执行 3 轮，任一失败即整体失败并生成审计 JSON。
19. Personal Jobs 与 Team 已纳入真实会话桌面验收：覆盖隔离空状态、空表单失败、创建、后端刷新恢复和中文术语边界。验收过程中发现并修复桌面深层会话 URL 只返回文件 404 的问题；自定义协议现在为安全的无扩展名 GET 导航回退 SPA shell，并使用根基址加载脚本和样式，不会掩盖缺失资源、写请求或 Range 请求。
20. 控制操作审批已与后端全部 20 类受管动作及其资源合同对齐，覆盖 Worktree、Skill、Plugin、Session 回退/分享和 Evolution；未知动作或资源仍保持 fail-closed。审批入口会基于当前工作区恢复服务器待审批列表，点击入口自动刷新，并保留手动刷新；通知式深链接后可继续执行“仅本次批准”或“拒绝”。通知目标只允许内部根相对路径，拒绝外部、协议相对、反斜杠和控制字符目标。
21. Timeline 的“重置到此点”和回退 Dock 的“恢复消息”已从旧的直接 `delete()` / `unrevert()` 调用迁移到受控 Session API。请求先进入审批中心，未批准前不乐观隐藏消息；拒绝不会改变会话，批准后才由封印执行器提交 Session/Event 状态。
22. 修复纯会话历史回退：没有文件补丁时，封印快照允许空 `files` / `targetRevisions`，但仍保留 Session revision、Event high-water mark、Git HEAD/index/dirty fence 和人工 L3 授权。`unrevert` 同时修复了 receipt digest 与原始 snapshot digest 混用、已加载 receipt 未传入 Repository 观察器，以及空文件计划伪造 target revision 三个缺陷。
23. Workflow 运行详情补齐本地化的执行条件、生命周期时间、权限、依赖、尝试次数与失败原因；稳定技术值保留原文，避免伪翻译。受控 Session API 错误现在可读取后端 `{ data: { message } }` 结构并向用户显示具体原因。
24. Plugin/Skill 中心完成真实桌面生命周期：技能停用/启用，以及插件检查、安装、启用、停用、可恢复卸载和恢复均通过同一控制审批中心逐次确认；新装和恢复插件保持默认停用。审批中心改为叠加打开，关闭后返回原设置操作，不再丢失上下文。
25. Plugin/Skill 卡片补齐显式启停状态、空状态、用户配置来源、中文安全发现、候选检查区和恢复编号；“删除”统一为生命周期含义更准确的“卸载”。
26. 修复跨功能冲突：项目级插件会产生未跟踪受管文件，原先导致纯对话回退错误要求干净 Git 快照。现在空文件计划可绑定真实 dirty fingerprint 并受 Git 漂移围栏保护；涉及文件写入的回退仍严格要求干净、可补偿源快照。
27. Plugin 更新与安全失败路径已纳入真实桌面验收：1.0.0 候选更新到 2.0.0 前必须获得新的 `plugin.update` 人工批准，更新后仍默认停用；含未声明联网和密钥访问的候选只允许只读检查，显示中文阻止原因，安装按钮保持禁用且受管插件列表不发生变化。
28. 修复扩展生命周期幂等代次：此前同一插件“卸载→恢复→再次卸载”会把第二次用户动作错误重放为第一次完成结果，界面提示成功但插件仍存在。现在桌面每次明确动作生成唯一 `cpr_` ID，Server 将其封入规范 claim；同一 ID 的网络重试保持幂等，不同用户动作不会串单。篡改恢复包的真实桌面路径会在审批后安全失败，显示中文可操作提示，不写回插件目录并保留恢复证据。
29. `typecheck:e2e` 已纳入全部桌面 `*.acceptance.ts`，避免验收脚本只在运行时才暴露类型错误。
30. Plugin/Skill 状态已纳入完整桌面进程重启验收：用户先在真实界面经审批停用 Skill、检查并安装 Plugin，再结束整个 Electron 进程树并复用同一隔离工作区、Arforge home 与 Electron profile 冷启动；重启后 Skill 仍停用，Plugin 版本和默认停用状态均由新后端进程恢复。
31. 个人工作区的 `recovery_required` 不再只是被动计数和内部 Run 文案：五类提醒均按当前语言转换为用户说明；待恢复执行会解释“上次执行未正常完成”，并提供可键盘访问的“查看恢复详情”，直接进入运行时透视。真实桌面 E2E 已使用失败 Durable Run 验证该路径。
32. Electron 原生“加载失败 / 窗口意外终止 / 未响应”对话已补齐简体中文、繁体中文和英文。按钮行为使用稳定动作 ID，不再比较显示文案，因此翻译不会改变重新启动、导出日志、继续等待或退出的控制语义。
33. 三个桌面 E2E 命令现在都会先构建 Desktop renderer，再执行验收；重复性 runner 只构建一次后运行多轮，避免源码已更新但 Electron 悄悄加载旧 bundle 的假失败或假通过。
34. Personal Workspace 的五类人工提醒不再是无响应的信息卡：恢复进入运行时透视，成本与记忆候选滚动并聚焦到对应摘要，成果和待批准任务进入所属会话的“定时、触发与等待”详情，复用唯一任务详情/审批控件。跨会话提醒会先打开任务所属会话，避免在错误会话操作。真实桌面 E2E 已连续 3 轮完成“创建待批准任务 → 工作区提醒 → 任务详情 → 批准 → 排队中”。

## 不同用户的推荐界面层级

### 新手

只需要看到：打开项目、新建会话、输入任务、模型、权限模式、清晰的执行状态、结果与文件变更。目标、工作流、记忆治理、团队、插件、数据库等入口默认折叠。错误信息必须说明“发生了什么、是否已处理、下一步点哪里”。

### 普通用户

在新手路径基础上增加：目标与任务、待发送消息、检查点与对话回退、项目级权限规则和基础记忆。界面使用中文意图名称，专业术语只作为括注或详情。

### 专业用户

可主动展开高级工具，访问自动化、后台任务、团队/子代理、Workflow、Plugin、Skill、运行时透视、诊断、数据库运维和能力映射。技术 ID、revision、digest、trace 等信息保留在详情层，不占据常用路径。

## 已知限制与下一批优先级

1. 顶栏部分功能仍依赖图标和悬停提示，首次可发现性一般；常驻执行状态条已缓解最关键的“是否卡住”问题。
2. 高级控制中心虽然已折叠并增加受众说明，后台自动任务和 Team 创建路径也已用户化，Workflow 关键深层字段已收敛，但部分后端生成的记录标题仍偏工程化；应继续按真实任务逐页收敛。
3. Workflow、Plugin/Skill、Memory、Evolution、Runtime insight、Personal Jobs、Team、审批中心、通知深链接和 Session 回退/恢复均已进入隔离桌面自动化 E2E；Plugin 更新、安全阻止、重复生命周期、篡改恢复失败、完整桌面进程重启后的扩展状态恢复，以及失败执行的页面级恢复入口均已覆盖。Electron 原生异常对话已本地化并通过单元测试，但主动杀死 renderer 的对话交互尚未自动化。Session Share 仍需要用户提供真实 HTTPS self-hosted Share Provider 的 base URL 与可见性选择，当前不得默认为公开分享。
4. 主入口包已缩小约 25%（gzip），但仍超过构建器 500 kB 建议值；Ghostty、会话页和语言/语法资源还需要继续按功能懒加载并建立启动性能预算。
5. 阶段 8.2 的多代理收益实验仍为 DO_NOT_PROMOTE；默认体验不应暗示多代理一定更快。
6. A2A、真实多租户和跨机器能力仍是本地开发合同，不应在普通用户界面宣称为生产云能力。
7. Personal Workspace 已满足五类提醒“有明确入口”的计划要求，成果提醒会进入现有任务详情查看已验证工件；但记忆候选目前只定位到隐私安全摘要。若要完成候选批准/拒绝，需补充带敏感度控制的详情 API、拒绝状态迁移和前端审查面板，不能让用户在看不到正文时盲目批准。
