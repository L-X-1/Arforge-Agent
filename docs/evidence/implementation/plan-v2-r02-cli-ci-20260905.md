1. 旧 bridge 测试要求 arforge.cmd 包含 MAIN_PY/main.py，实际 launcher 已是 node→TS。先复现 1 failed，再改为验证 TS launcher、禁止 Python main、传递退出码。
2. 新增 CI 结构断言，先得到 3 failed / 1 passed：拒绝失效 capability-eval；所有平台安装 TS 依赖；区分静态合同与运行时回放。
3. CI 将 bun install --frozen-lockfile 提升为 Linux/Windows 共同步骤；Linux 使用本机正确的 bun 文件名。brand 测试同步按 OS 选文件名，不额外保留 Linux bun.exe 伪入口。
4. CI 静态检查明确为 node bin/arforge.js capabilities evaluate --json；doctor 同样直接走 TS。既有运行时回放保留，增加 Core Golden/Evaluation 测试；该合同测试不是完整 runtime eval、不是远程模型评估。
5. bridge 测试 54 处缺 Bun 后直接 return 的静默通过改为统一前提检查：本地明确 skip，CI 明确 fail；新增缺前提回归。Python 3.10 读取 TOML 使用已锁定 tomli fallback。
6. 新增真实 Windows CMD 对比测试：成功静态查询（中文且含空格 workspace）和未知命令；比较 CMD wrapper 与直接 TS 的 stdout/stderr/退出码，使用独立 profile。
