R13 MCP catalog 与缓存工具的 declared-scope 代际边界（2026-09-15）

结论

MCP 公共 prompts/resources/resourceTemplates 目录读取、握手阶段缓存的 tools 投影，以及 capability catalog projection，现在在创建 SDK 请求前都解析同一 MCP.declaredScope。连接对象仍可能因恢复/配置刷新暂时存在，但配置缺失、远端 endpoint 无法规范化或本地 frozen connect intent 无法重建时，目录与缓存工具均 fail-closed，不向旧 transport 发请求，也不把旧工具或旧 capability 元数据继续暴露给模型/API/CLI。

本切片只收紧了 MCP service 内部的 scope 边界；没有把 HTTP/CLI 目录读取声称成已经经过 control Action/Gateway。

实现

- packages/arforge/src/mcp/index.ts
- collectFromConnected 在 McpCatalog.fetch 之前调用 declaredScope；无 scope 时记录可审计 warning 并返回空目录，因此不会消耗分页/transport budget。
- MCP.tools 对握手缓存的工具定义使用同一 scope fence，配置漂移期间不再继续产生 model-facing Tool.Def。
- 已发布 generation 的 tools/list_changed 刷新同样在 SDK 请求前通过 scope fence；初始握手仍由连接意图自身验证。
- MCP.capabilities 与 MCP.catalog().capabilities 过滤 disconnected、旧 generation 和无 scope registry 条目。
- MCP.instructions 过滤无 scope 的 retained client。
- existing generation/client fence、registry replacement 与 read/prompt lease 检查保持不变。
- packages/arforge/test/mcp/lifecycle.test.ts
  - 添加受控配置快照 fixture：首次配置读取建立连接，后续读取返回空配置；fixture 同时声明 tools/prompts/resources，覆盖三类目录。
- 目录读取返回空且真实 MCP server 的三类 catalog request 计数不变；缓存工具、capability projection 与 instructions 也不再返回，tools/list_changed 也不触发新的 tools/list。

验收证据

- Prompt/resource projection：D:\bun\bin\bun.exe test test/mcp/resource-projection.test.ts --timeout 30000；11 pass / 0 fail / 48 assertions，exit 0；其中 scope 缺失路径在 permission/transport 前被阻断。
- 修改文件 Prettier 通过；限定 git diff --check exit 0。
- 根目录 scoped Oxlint（MCP index、resource projection、ToolRegistry、lifecycle fixture）：0 errors，36 warnings；warning 为仓库既有规则命中，本轮未引入 error。
- Arforge 包级 typecheck 仍被既有 packages/tui JSX/BaseRenderable 诊断阻断；本切片没有新增 MCP/command 诊断。

测试只使用临时 HTTP MCP fixture、临时配置和受控请求计数，不使用真实凭据，不触碰用户数据；不涉及 full sandbox。
