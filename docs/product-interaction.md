# 面向用户的交互设计原则

> 来源: ARFORGE.md（2026-08-11 拆分）
> 适用对象: 所有面向用户的界面与流程的开发者
> 优先级: 低于 ARFORGE.md 的执行准则；这是产品开发规范，不是 Agent 执行指令

## 原则

1. **后端功能成熟，前端简单易懂**：把复杂逻辑放在后端，用户界面只做清晰呈现和少量必要操作；不在界面上暴露内部实现细节。

2. **操作逻辑简单**：默认只读展示；任何需要用户做的事（审批、确认、配置、校验）都应是明确的按钮/入口，且文案直接说明后果。

3. **自动与人工分明**：每个面向用户的界面必须明确标注哪些是系统自动执行的（如自动记录、自动验证、自动压缩），哪些需要用户决策（如审批、回滚、配置）。用 `自动` / `人工` 标签区分，不给用户暗示"需要操作"实际上全自动的功能。

4. **用户可见文案用中文口语化**：避免技术黑话（如"上下文分层编译"要配一句人话解释），专业术语首次出现时给出简单说明。

5. **新功能上线前自查**：用户能否不看文档就明白"这是什么、是否需要我做什么、结果在哪看"。

## 验收清单

- [ ] 复杂逻辑是否全部在后端，界面只做呈现与必要操作？
- [ ] 所有需要用户决策的入口是否文案直接说明后果？
- [ ] 系统自动执行与用户决策是否用 `自动` / `人工` 标签区分？
- [ ] 用户可见文案是否中文口语化，术语首次出现是否有解释？
- [ ] 新功能上线前，新用户能否不看文档就理解三个问题：这是什么、是否需要我做什么、结果在哪看？
